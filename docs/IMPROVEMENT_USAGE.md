# Воспроизведение улучшений v2

Все работы выполняются в отдельном окружении Miniconda `.venv`, только на готовых TACO и TrashCan. Физические камеры и полевые условия не используются. Исходная версия сохранена в `models/baseline_v1`.

## Данные

```powershell
.\.venv\python.exe scripts\download_data.py taco --mirror
.\.venv\python.exe scripts\download_data.py trashcan
.\.venv\python.exe scripts\restore_full_taco.py
.\.venv\python.exe scripts\prepare_v2.py
.\.venv\python.exe scripts\prepare_negatives.py
.\.venv\python.exe scripts\admit_negatives.py
```

Для текущей локальной установки данные уже подготовлены. Не повторять эти команды во время обучения: входы серий фиксируются по контрольным суммам. Рабочие изображения ограничены длинной стороной 1600px, полноразмерные оригиналы сохраняются отдельно в `data/raw/taco_full`.

Отрицательные примеры — фрагменты готовых изображений TACO без пересечения исходных bbox. Контактные листы проверены визуально; 19 сомнительных кандидатов исключены, 141 принят. Все фрагменты остаются в той же выборке, что и исходный снимок. Это не независимая исчерпывающая переразметка набора. Идентификаторы исключений привязаны к воспроизводимой генерации текущих исходных аннотаций и seed.

## Серии и возобновление

```powershell
.\.venv\python.exe scripts\v2_pipeline.py
.\.venv\python.exe scripts\stability_v2.py
```

Обучения идут последовательно, чтобы ограничить расход ОЗУ. Готовая серия с `summary.json` повторно не запускается. Частичная серия возобновляется из `weights/last.pt` с состоянием оптимизатора. Если обучение завершилось и checkpoint уже очищен от оптимизатора, но отчёт не успел сохраниться, runner восстанавливает отчёт через validation готового `best.pt`.

Основной бюджет — до 80 эпох, patience=15; для контрольного дообучения и отдельной аугментации — до 15 эпох, для каждого группового CV-фолда — до 20. Число фактически выполненных эпох берётся из CSV. Короткий CV является проверкой устойчивости при ограниченном бюджете, а не полным 80-эпоховым CV.

Основной критерий выбора — validation mAP50–95. Два seed сравниваются описательно, без заявления доверительного интервала. Test-группы исключены из обучений, подбора и всех CV-фолдов. Исторический test уже оценивался в v1 и не считается новой слепой проверкой.

Перед возобновлением или использованием готовой серии проверяются её входы и рецепт: архитектура, начальные веса, разрешение, batch, seed, бюджет, patience и аугментация. Изменение этих параметров требует нового имени серии. Число загрузчиков `--workers` можно менять для настройки расхода ОЗУ; фактические параметры обучения записываются в `summary.json`. Старые готовые серии без `run_recipe.json` проверяются по сводке и сохранённому `args.yaml`.

## Итоговая оценка и установка настроек

```powershell
.\.venv\python.exe scripts\finalize_v2.py
.\.venv\python.exe scripts\export_check_v2.py
.\.venv\python.exe scripts\report_v2.py
.\.venv\python.exe scripts\verify_v2.py
```

Запускать после завершения main pipeline и проверки устойчивости. Finalizer выбирает по validation, сравнивает с сохранённой v1, фиксирует пороги, затем считает парную test-оценку. Если кандидат хуже baseline на общей validation-выборке, сохраняется baseline.

Все заключительные действия последовательно выполняет `scripts/complete_v2.py`: оценка, экспорт, проверка фото/видео, unit-тесты, программная проверка окна, проверка зависимостей, обновление lock-файла и отчёта. Ключ `--wait-for-training` позволяет дождаться сводок основного обучения и устойчивости. Тяжёлые проверки не запускаются параллельно с обучением. Программная проверка окна не заменяет визуальный просмотр его оформления.

balanced выбирается по F1, recall — F2, precision — F0.5. SAHI получает отдельные пороги. AP рассчитывается единым методом для парного сравнения: один класс, IoU 0.50–0.95, 101 точка интерполяции, до 100 рамок на изображение. Эти числа не смешиваются напрямую со старым отчётом Ultralytics.

## Приложение

После итоговой установки конфигураций `run_app.bat` использует выбранные модели и режимы. В интерфейсе доступны «Баланс», «Меньше пропусков», «Меньше ложных рамок» и обработка «По фрагментам (SAHI)».

```powershell
.\.venv\python.exe -m litter_detector image photo.jpg --profile land --operating-mode recall --output outputs\recall
.\.venv\python.exe -m litter_detector image photo.jpg --profile land --sliced --operating-mode precision --output outputs\sliced
```

SAHI предназначен для файлов и может существенно замедлять обработку. Размеры фрагмента 640 и 960 сравниваются на validation; выбранный размер сохраняется в конфигурации профиля. Если все изображения меньше 640px, дополнительный размер не проверяется. Скорость на файлах не является измерением задержки физической камеры. ONNX экспортируется отдельно с opset 18; PyTorch CUDA сохраняется основным backend, пока иной backend не подтвердил полезный выигрыш без неприемлемого изменения результатов.
