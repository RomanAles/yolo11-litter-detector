# Запуск и воспроизведение

Команды выполняются из корня проекта. Python берётся из `.venv`, активация окружения не обязательна.

## Установка

```powershell
.\scripts\bootstrap.ps1
```

Скрипт использует Miniconda `D:\miniconda3`; другой путь можно передать через `-CondaPython`. В `.venv` устанавливаются Python 3.11 и точные версии из `requirements-lock.txt`, включая CUDA-сборку PyTorch. Среда `base` не используется для работы приложения. Не добавляйте её `site-packages` в `PYTHONPATH`.

## Оконное приложение

Запустить `run_app.bat` либо:

```powershell
.\run_app.ps1
```

Выбрать профиль `land` / `underwater`, режим `image` / `folder` / `video`, источник и папку результатов. Пустое поле Confidence использует порог профиля, подобранный на validation. Кнопка остановки завершает текущий кадр и закрывает видео. Профиль и источник фиксируются на момент запуска обработки; их изменение в форме не меняет уже выполняемую задачу.

Режим `camera` предусмотрен только для обычной веб-камеры и требует явного запуска пользователем. В этом этапе физические камеры не подключались; подводный профиль принимает только файлы.

## Командная строка

```powershell
.\.venv\python.exe -m litter_detector image 'путь\фото.jpg' --profile land --output outputs\photo
.\.venv\python.exe -m litter_detector folder 'путь\изображения' --profile underwater --output outputs\batch
.\.venv\python.exe -m litter_detector video data\samples\underwater_dataset_sequence.mp4 --profile underwater --output outputs\video
```

Параметры `--conf 0.4`, `--device cpu`, `--model путь\веса.pt` переопределяют настройки. Подмена модели предполагает, что пользователь выбрал подходящие классы: обычные COCO-веса не являются специализированным детектором мусора.

На фото создаются `*_detected.jpg` и одноимённый JSON. При обработке папки сохраняются вложенные пути; расширения входов разделяются дополнительной папкой, чтобы `same.jpg` и `same.png` не перезаписывали друг друга. Ошибки отдельных входов записываются в `batch_summary.json`.

Видео сохраняется как `detected.mp4`, журнал кадров — `detected.jsonl`, сводка — `detected.summary.json`. Записываются все читаемые кадры с исходным постоянным FPS, звук не переносится. Для VFR-видео исходные переменные временные интервалы не сохраняются: сначала требуется нормализация в CFR. Скорость обработки не меняет FPS записанного файла.

Демонстрационная последовательность `underwater_dataset_sequence.mp4` собрана из кадров одного отложенного ролика TrashCan с назначенными 12 FPS; это не исходное видео камеры. Происхождение кадров сохранено рядом в JSON.

## Данные, обучение, оценка

```powershell
.\.venv\python.exe scripts\download_data.py taco --mirror
.\.venv\python.exe scripts\download_data.py trashcan
.\.venv\python.exe scripts\prepare_data.py all
.\.venv\python.exe scripts\audit_splits.py
.\.venv\python.exe scripts\train_models.py all --epochs 30
.\.venv\python.exe scripts\evaluate_models.py all
```

Для обучения требуется `models/pretrained/yolo11n.pt` из официального [релиза Ultralytics](https://github.com/ultralytics/assets/releases/download/v8.3.0/yolo11n.pt). Источник и SHA256 локального файла находятся рядом в `.provenance.json`. Для каждого профиля запускается YOLO11n с 30 эпохами, seed=42 и ранней остановкой после 8 эпох без улучшения. При прерывании использовать `--resume`; существующие готовые модели без этого не перезаписываются.

Точный состав данных описан в [DATASETS.md](DATASETS.md). Данные уже подготовлены локально; повторная загрузка не требуется для обычного запуска. Архив зеркала TACO поддерживает докачку частями; в памяти удерживается не более шести блоков загрузки. Повторная подготовка отказывается смешивать другое разбиение с существующим и проверяет хеши исходных изображений и аннотаций до записи результатов. Если источники изменились, нужен новый набор в отдельной папке. После прерванной первой подготовки без манифеста рабочие копии создаются заново.

Оценка выбирает Confidence по максимальному F1 на validation, затем считает показатели на test. Изменение порога по результатам test в скрипте не выполняется. AP использует низкий порог для построения кривой; precision/recall рабочего режима отдельно рассчитаны при выбранном пороге и IoU=0.5. Это разные показатели.

## Программные проверки

```powershell
.\.venv\python.exe -m pytest -q --basetemp .cache\pytest-local
.\.venv\python.exe -m litter_detector.ui --smoke-test
```

Проверяются разметка, разбиение, ограниченный буфер, Unicode-пути, пакетная обработка и длительность записи. Синтетические массивы в unit-тестах используются только как фикстуры программных функций; обучение проводится исключительно на публичных датасетах.
